# Choose the first useful study loop and its boundaries

Type: grilling
Labels: wayfinder:grilling
Status: resolved
Blocked by: none
Parent: [OwlPilot — Personal academic co-pilot](../map.md)

## Question

What destination, audience, first usable experience, initial data source, and safety boundaries should constrain OwlPilot's plan?

## Answer

The user explicitly accepted both initial recommendations: plan a working, local-first, personal-use OwlPilot preserving the existing design and using It for page-to-agent interactions. The planning destination is an implementation-ready specification and phased build plan, followed by implementation only after agreement.

In the breadth-first charting round the user selected:

- **Focused study loop:** daily priorities → log a mistake → generate a personalized review guide. Other prototype screens stay visible but explicitly marked as demo until connected.
- **Files first:** start from user-supplied course materials such as syllabi, deadline lists, notes, and graded feedback. Live D2L/DegreeWorks is not required for the first usable release.
- **Keep the boundaries:** do not submit graded work, post discussions, write graded work, open timed assessments, or change D2L state. Explicit approval is required before any external write. A click on a demo approval is not permission to perform a real external action.

These are scope-setting answers obtained during charting, not implementation authorization. Detailed import, runtime, policy enforcement, state, and verification contracts remain undecided.
